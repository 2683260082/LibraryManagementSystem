## 2. E-R 关系

```
   ┌────────────┐          ┌────────────┐
   │   users    │          │    books   │
   │   读者/管理员│          │    图书     │
   ├────────────┤          ├────────────┤
   │ PK id      │          │ PK id      │
   │ UQ username │          │    isbn    │
   │    password │          │    title   │
   │    role     │          │    author  │
   │    name     │          │    ...     │
   │    status   │          │    total   │
   └──────┬─────┘          │    available│
          │                └──────┬─────┘
          │       1                │
          │                        │
          │       n                │
   ┌──────▼────────────────────────▼─────┐
   │              borrows                 │
   │              借阅记录                 │
   ├─────────────────────────────────────┤
   │ PK id                               │
   │ FK user_id  → users.id              │
   │ FK book_id  → books.id              │
   │    borrow_date    借阅日期            │
   │    due_date       应还日期            │
   │    return_date    归还日期(NULL=未还) │
   │    fine           违约金              │
   └─────────────────────────────────────┘

   基数关系：
     users  1 ──── n  borrows     一个读者可有多条借阅记录
     books  1 ──── n  borrows     一本书可被多次借出
```

**联系类型**：`borrows` 是典型的**多对多关联表**——一个读者可借多本书，一本书可被多个读者借阅，通过 `borrows` 拆解为两个一对多关系。

## 3. 表结构

### 3.1 users — 用户表

| 字段 | 类型 | 约束 | 含义 | 说明 |
|------|------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 用户ID | 自增主键 |
| `username` | TEXT | **UNIQUE** NOT NULL | 登录用户名 | 唯一约束，注册重复时抛 `IntegrityError` |
| `password` | TEXT | NOT NULL | 密码 | **哈希存储**，非明文，`generate_password_hash()` 生成 |
| `role` | TEXT | NOT NULL DEFAULT `'reader'` | 角色 | `admin`=管理员 / `reader`=读者 |
| `name` | TEXT | — | 真实姓名 | 展示用 |
| `phone` | TEXT | — | 手机号 | 选填 |
| `status` | TEXT | NOT NULL DEFAULT `'active'` | 账号状态 | `active`=正常 / `deleted`=已注销（软删除） |
| `created_at` | TEXT | — | 注册时间 | `YYYY-MM-DD HH:MM:SS` |

**关键设计：`status` 软删除**

```sql
-- 注销读者时执行的是 UPDATE，不是 DELETE
UPDATE users SET status = 'deleted' WHERE id = ? AND role = 'reader' AND status = 'active';

-- 登录时同时校验状态
SELECT * FROM users WHERE username = ?
-- 通过条件：user 存在 AND status = 'active' AND 密码哈希匹配
```

若采用物理 `DELETE`，该读者的全部借阅记录会一并丢失，而借阅记录是业务凭证，需要可追溯。
软删除后：账号不可再登录、不再出现在管理列表，但历史借阅完整保留。

### 3.2 books — 图书表

| 字段 | 类型 | 约束 | 含义 | 说明 |
|------|------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 图书ID | 自增主键 |
| `isbn` | TEXT | — | ISBN 号 | 可空 |
| `title` | TEXT | NOT NULL | 书名 | **唯一非空字段**，检索主维度 |
| `author` | TEXT | — | 作者 | 可空 |
| `publisher` | TEXT | — | 出版社 | 可空 |
| `category` | TEXT | — | 分类 | 用于分类筛选，已建索引 |
| `price` | REAL | DEFAULT 0 | 价格（元） | 服务端校验非负 |
| `total` | INTEGER | NOT NULL DEFAULT 1 | 馆藏总册数 | 服务端校验 ≥ 1 |
| `available` | INTEGER | NOT NULL DEFAULT 1 | **可借册数** | 系统自动维护，不允许手工填写 |
| `created_at` | TEXT | — | 入库时间 | — |

**关键设计：`total` 与 `available` 分离**

| 字段 | 谁能改 | 说明 |
|------|--------|------|
| `total` | 管理员（表单填写） | 采购新增时录入，校验不得小于已借出数量 |
| `available` | **仅系统** | 借书 `-1`，还书 `+1`（上限 `total`），编辑时按 `total - 已借出数` 反推 |

分开存的原因：`total` 是**馆藏规模**这一静态属性，`available` 是**实时流通状态**这一动态值。
若只存一个字段，则无法表达"共 10 本、已借走 3 本"这一核心信息。

**库存一致性保障**（三重防线）：

| 场景 | 防护 |
|------|------|
| 借书并发导致超借 | 条件更新 `WHERE available > 0`，靠 `rowcount` 判成败 |
| 还书导致库存超出总数 | `available = MIN(available + 1, total)` 上限保护 |
| 编辑时把总数改到小于已借出数 | 服务端校验拒绝：`total < borrowed` 时报错 |

### 3.3 borrows — 借阅记录表

| 字段 | 类型 | 约束 | 含义 | 说明 |
|------|------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 记录ID | 自增主键 |
| `user_id` | INTEGER | NOT NULL, FK→users.id | 借阅人 | 外键 |
| `book_id` | INTEGER | NOT NULL, FK→books.id | 图书 | 外键 |
| `borrow_date` | TEXT | NOT NULL | 借阅日期 | `YYYY-MM-DD` |
| `due_date` | TEXT | NOT NULL | 应还日期 | 借阅日 + 60 天 |
| `return_date` | TEXT | 可空 | 归还日期 | **NULL 表示尚未归还** |
| `fine` | REAL | DEFAULT 0 | 违约金（元） | 归还时按逾期天数 × 0.1 计算 |

**关键设计：`return_date` 可空即状态位**

系统不单独设"借阅状态"字段，而是用 `return_date IS NULL` 表达"在借"：

```sql
-- 统计当前借出数量
SELECT COUNT(*) FROM borrows WHERE return_date IS NULL;

-- 查询逾期未还
SELECT * FROM borrows
 WHERE return_date IS NULL
   AND due_date < date('now');
```

这样避免了"状态字段"与"归还日期"可能出现的不一致（例如状态标为已还但 `return_date` 为空）。
**单一事实来源**是数据库设计中的重要原则。

**日期存储格式**：统一 `YYYY-MM-DD` 纯日期字符串。

- 优点：SQLite 的 `julianday()` / `date()` 可直接做日期运算
- 注意：不存时间戳，因为借还业务只关心"哪一天"，不关心具体时刻

## 4. 索引设计

```sql
CREATE INDEX IF NOT EXISTS idx_borrows_user   ON borrows(user_id, return_date);
CREATE INDEX IF NOT EXISTS idx_borrows_book   ON borrows(book_id, return_date);
CREATE INDEX IF NOT EXISTS idx_books_category ON books(category);
```

| 索引 | 覆盖场景 | 作用 |
|------|----------|------|
| `idx_borrows_user` | 我的借阅列表、重复借阅校验、注销前查在借数 | 这是访问频率最高的查询路径 |
| `idx_borrows_book` | 图书删除校验、库存反推、按书查借阅历史 | 后台统计与校验依赖 |
| `idx_books_category` | 图书列表按分类筛选 | 分类下拉框 + 筛选 |

**为什么是复合索引 `(user_id, return_date)`？** 索引列顺序决定了可用性：
查询条件通常是 `WHERE user_id = ? AND return_date IS NULL`，两列同时命中时效率最高；
而只按 `user_id` 查时，该索引仍然可用（最左前缀原则）。若顺序写反（`return_date` 在前），
单列 `user_id = ?` 就无法利用索引了。

## 5. 约束与完整性

| 约束类型 | 位置 | 作用 |
|----------|------|------|
| `UNIQUE` | `users.username` | 防止重复用户名 |
| `NOT NULL` | `users.username/password/role/status` | 账号必需字段 |
| `NOT NULL` | `books.title/total/available` | 图书必需字段 |
| `NOT NULL` | `borrows.user_id/book_id/borrow_date/due_date` | 借阅必需字段 |
| `FOREIGN KEY` | `borrows.user_id`, `borrows.book_id` | 声明引用关系 |
| 业务校验 | 应用层 `_parse_book_form()` | 价格非负、总数 ≥ 1、总数不小于已借出数 |
| 业务校验 | 应用层 `borrow()` / `return_book()` | 库存不可透支、重复借阅拦截、越权拦截 |

> **关于外键的说明**：SQLite 默认**不启用**外键强制（需 `PRAGMA foreign_keys=ON`）。
> 本项目通过**应用层显式校验**保证完整性——删除图书前检查借阅记录、注销前检查在借数量，
> 因此即使外键未强制，也不会产生违反业务规则的数据。答辩时被问到可如实说明这一取舍。

## 6. 初始化与迁移

### 6.1 初始化（幂等）

`init_db()` 在**模块导入时**执行（非仅 `__main__` 中），保证 `python app.py`、`flask run` 等方式都能拿到可用数据：

```python
init_db()
   │
   ├─ 1. CREATE TABLE IF NOT EXISTS ...   ← 已存在则跳过
   ├─ 2. _migrate(conn)                   ← 为旧库补齐缺失字段
   └─ 3. SELECT COUNT(*) FROM users
        ├─ > 0 → 已有数据，直接返回        ← 保证演示数据只写一次
        └─ = 0 → 插入 2 个账号 + 8 本图书
```

**幂等三要素**：建表用 `IF NOT EXISTS`、迁移先查字段是否存在、演示数据先查行数。

### 6.2 迁移

```python
def _migrate(conn):
    columns = [r[1] for r in conn.execute("PRAGMA table_info(users)")]
    if "status" not in columns:                          # 旧库缺少 status 字段
        conn.execute("ALTER TABLE users ADD COLUMN status TEXT NOT NULL DEFAULT 'active'")
    conn.execute("UPDATE users SET status='active' WHERE status IS NULL OR status=''")
```

`ALTER TABLE ... ADD COLUMN` 同时指定 `DEFAULT 'active'`，因此历史数据会自动获得正常状态，无需额外修复语句。

> 课程设计未引入 Alembic 等迁移框架，采用**启动时字段级检查**这一最小可用方案，
> 足以支撑"旧库升级到新版"这一场景，且代码量小、易于讲解。
