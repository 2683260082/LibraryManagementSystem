## 2. 测试范围与策略

系统采用**两层测试**，互补覆盖：

| 层次 | 单元测试 | 端到端测试 |
|------|----------|------------|
| 文件 | `unit_test\test_library.py` | `smoke_test.py` |
| 方式 | Flask 内置 `test_client()`，不启动真实服务 | 真实 HTTP 请求，需服务运行中 |
| 数据库 | 每个用例**独立临时库**，用完自动删除 | 用真实 `library.db`，结束自动清理 |
| 关注点 | 单个功能的输入输出与状态变化 | 整条业务链路能否走通 |
| 依赖 | 无（可随时执行） | 需先启动服务 |

**隔离设计**（关键）：单元测试在 `setUp()` 中创建 `tempfile.TemporaryDirectory()` 临时数据库，
`tearDown()` 中恢复原始路径并删除临时目录。**测试永远不会污染业务数据**，可反复执行。

```python
def setUp(self):
    self._tmpdir = tempfile.TemporaryDirectory()          # 建临时目录
    self._orig_db_path = app_module.DB_PATH               # 备份原路径
    app_module.DB_PATH = os.path.join(self._tmpdir.name, "test.db")  # 指向临时库
    app_module.init_db()                                  # 建表 + 写演示数据

def tearDown(self):
    app_module.DB_PATH = self._orig_db_path               # 恢复原路径
    self._tmpdir.cleanup()                                # 删除临时目录
```

**自清理机制**：脚本以 `冒烟测试` 为标记创建临时数据，结束时按标记清除
（顺序：先删借阅记录，再删图书，最后删账号），**跑完后数据库回到 2 用户 / 8 图书 / 0 借阅的初始状态**。

**自检机制（第 15 阶段）**：清理完成后立即校验数据库状态，一旦有数据残留或出现孤儿记录，
测试当场 FAIL。这一设计是为了避免脏数据无声无息地留在交付用的演示库里。

## 8. 测试设计要点

供答辩时说明"测试是怎么写的"：

| 要点 | 做法 |
|------|------|
| **数据隔离** | 每个用例独立临时数据库，跑完自动删，不污染业务数据 |
| **真实状态断言** | 不只看页面提示文字，还会**直接查数据库**确认 `available`、`status` 等字段的真实值 |
| **边界与异常** | 覆盖 `page=abc`、`page=-99`、`price=abc`、`total=0`、`total=-5` 等非法输入 |
| **并发模拟** | 库存压至 0 后连续借阅，验证条件更新生效、库存不为负、无残留记录 |
| **日志可追踪** | 每个测试方法带 `_print()` 输出，执行过程可逐步回看 |
| **文档规范** | 每个测试方法带中文 docstring 说明用途与预期，关键步骤有断言说明 |
