# 01 需求分析

| 日期 | 修改内容 |
|------|----------|

## 1. 项目背景

传统图书馆依靠人工登记借还，存在三类典型问题：

1. **易出错**：手写登记笔迹潦草、字数统计靠人工核对，库存数与实际借出数经常对不上。
2. **难查询**：想查"某本书谁借了"、"某人逾期几天"需要翻阅纸质台账。
3. **无逾期管理**：应还日期靠人工记忆，违约金计算容易漏算、算错。

本项目目标是构建一套**可独立运行**的图书借阅管理系统，覆盖图书管理、读者管理、借还业务、逾期计费与检索统计的完整闭环。

## 2. 项目目标

- 提供读者自助的图书检索与借还能力，减少人工登记
- 库存数由系统自动维护，杜绝超借与人工统计错误
- 逾期自动判定并计算违约金，规则可配置
- 提供多维度检索与统计，支持管理员快速掌握馆藏与流通情况
- 代码结构清晰、带完整注释与测试，便于课程设计答辩讲解

## 3. 用户角色

系统只设两种角色，通过 `users.role` 字段区分，权限边界清晰：

| 角色 | 标识 | 数量限制 | 核心诉求 |
|------|------|----------|----------|
| 管理员 | `admin` | 由初始数据写入，不开放注册 | 掌握馆藏与流通全貌，管理图书和读者 |
| 读者 | `reader` | 无限制，可自助注册 | 快速找到书、借走、按时归还 |

> **设计说明**：管理员账号不在注册页开放，避免普通用户注册后自行提权。初始账号 `admin` 由系统首次建库时写入。

## 4. 功能需求

### 4.1 认证与账号管理

| 编号 | 功能 | 说明 |
|------|------|------|
| F-01 | 读者注册 | 必填用户名、姓名、密码；手机号选填。用户名仅允许字母数字下划线，长度 3–30；密码至少 6 位 |
| F-02 | 登录 | 校验账号密码，成功写入会话（session）；失败统一提示，不区分"用户不存在"与"密码错误" |
| F-03 | 退出登录 | 清空会话并跳转登录页 |
| F-04 | 已登录访问登录/注册页 | 直接跳转控制台，避免出现"登录框套着导航栏"的矛盾界面 |
| F-05 | 账号注销 | 仅管理员操作；采用软删除，历史借阅记录保留 |

**权限控制要求**：未登录访问任何受保护页面须跳转登录页；读者访问管理员页面须被拦截并提示"该功能仅管理员可用"。

### 4.2 图书管理

| 编号 | 功能 | 角色 | 说明 |
|------|------|------|------|
| F-06 | 图书检索 | 读者/管理员 | 支持书名、作者、ISBN 三个字段模糊搜索，叠加分类精确筛选，结果分页 |
| F-07 | 新增图书 | 管理员 | 服务端校验书名必填、价格非负、总数 ≥ 1 |
| F-08 | 编辑图书 | 管理员 | 馆藏总数不得小于已借出数量；可借数由系统反推，不允许手工填写 |
| F-09 | 删除图书 | 管理员 | 只要该书存在借阅记录（含已归还）即拒绝删除，防止产生孤儿借阅记录 |

### 4.3 读者管理

| 编号 | 功能 | 角色 | 说明 |
|------|------|------|------|
| F-10 | 读者列表 | 管理员 | 展示每位读者的当前在借数量，分页显示 |
| F-11 | 注销读者 | 管理员 | 有未还图书时拒绝注销；否则置 `status=deleted`，借阅历史保留 |

### 4.4 借还业务

| 编号 | 功能 | 角色 | 说明 |
|------|------|------|------|
| F-12 | 借书 | 读者/管理员 | 库存不足拒绝；同一本书未归还前不可重复借阅；借阅期 60 天 |
| F-13 | 还书 | 本人或管理员 | 管理员可代还他人图书；他人借阅记录无权操作 |
| F-14 | 我的借阅 | 读者/管理员 | 分页展示本人全部借阅记录，含状态标记与应计违约金 |
| F-15 | 全馆借阅记录 | 管理员 | 按状态（全部/在借/逾期）与书名、读者姓名筛选，分页 |

### 4.5 统计与展示

| 编号 | 功能 | 说明 |
|------|------|------|
| F-16 | 控制台统计 | 图书种类、馆藏总量、当前借出；管理员额外显示注册读者数 |
| F-17 | 最近借阅 | 管理员看全馆最新 8 条；读者看本人最近 8 条 |

## 5. 业务规则

| 规则编号 | 规则 | 实现位置 |
|----------|------|----------|
| B-01 | 借阅期限 60 天 | `DATABASE_DAYS` 常量 |
| B-02 | 逾期违约金 0.1 元/天 | `FINE_PER_DAY` 常量 |
| B-03 | 同一本书未归还前不可重复借阅 | `borrow()` 重复在借校验 |
| B-04 | 库存不足时拒绝借出，`available` 永不为负 | 条件更新 `WHERE available > 0` |
| B-05 | 有借阅记录的图书不可删除 | `book_delete()` 校验 |
| B-06 | 有未还图书的读者不可注销 | `reader_delete()` 校验 |
| B-07 | 归还时库存回补不得超过馆藏总数 | `MIN(available + 1, total)` |
| B-08 | 注销读者保留历史借阅凭证 | 软删除 |

## 6. 非功能需求

| 类别 | 要求 | 达成方式 |
|------|------|----------|
| 可用性 | 双击脚本即可启动，无需配置数据库 | SQLite 单文件 + 一键启动脚本 |
| 安全性 | 密码不明文存储 | `generate_password_hash` 加盐哈希 |
| 安全性 | 防 SQL 注入 | 全部使用参数占位符 `?` |
| 安全性 | 防跨站脚本 | 模板自动转义，动态内容传给 JS 时用 `tojson` |
| 安全性 | 防会话被 JS 窃取 | Cookie 开启 `HttpOnly` |
| 完整性 | 借书过程不产生半截数据 | 事务包裹扣库存与写借阅记录 |
| 可扩展性 | 业务参数集中管理 | 常量集中定义，改一处即生效 |
| 可维护性 | 数据量大时不卡顿 | 列表全部分页，每页 10 条，上限 100 |
| 可测试性 | 核心逻辑可验证 | 40 个单元测试 + 36 项端到端断言 |
| 可移植性 | 中文界面不乱码 | 输出统一 UTF-8 编码 |

## 7. 用例概览

```
                 ┌────────────────────────────┐
                 │           图书管理系统      │
                 └────────────────────────────┘
                             │
       ┌─────────────────────┼─────────────────────┐
       │                     │                     │
┌──────▼──────┐        ┌─────▼──────┐        ┌─────▼──────┐
│  匿名用户   │        │    读者    │        │  管理员    │
└──────┬──────┘        └─────┬──────┘        └─────┬──────┘
       │                     │                     │
  注册(F-01)            检索图书(F-06)          图书增删改(F-07~09)
  登录(F-02)            借书(F-12)              读者管理(F-10~11)
                         还书(F-13)              全馆记录(F-15)
                         我的借阅(F-14)          统计面板(F-16~17)
```

| 用例 | 参与者 | 前置条件 | 主流程 | 后置条件 |
|------|--------|----------|--------|----------|
| UC-01 注册 | 匿名用户 | 用户名未被占用 | 填表 → 校验 → 写入 `users` → 跳登录页 | 新增 reader 账号 |
| UC-02 登录 | 任意用户 | 账号存在且未注销 | 输入凭据 → 校验 → 写 session → 控制台 | 建立登录态 |
| UC-03 借书 | 读者 | 未借过该书且有库存 | 选书 → 提交 → 条件扣库存 → 写借阅记录 | `available-1`，生成应还日期 |
| UC-04 还书 | 本人/管理员 | 该记录尚未归还 | 确认 → 算违约金 → 写归还日期 → 回补库存 | 记录关闭，`available+1` |
| UC-05 注销读者 | 管理员 | 该读者无未还图书 | 选人 → 确认 → 置 `status=deleted` | 账号不可登录，借阅历史保留 |

## 8. 运行环境

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10 及以上（跨平台也可运行） |
| Python | 3.8 及以上（本项目在 Python 3.11.9 验证） |
| 第三方依赖 | Flask 3.x（仅此一项） |
| 数据库 | SQLite（Python 内置，无需额外安装） |
| 浏览器 | 任意现代浏览器 |
