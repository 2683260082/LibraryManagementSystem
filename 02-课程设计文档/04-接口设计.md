## 2. 通用约定

### 2.1 会话与鉴权

登录成功后 `session` 写入四个字段：

```python
session.update(user_id=..., username=..., role=..., name=...)
```

后续请求由 Flask 自动携带签名 Cookie（`library_session`），属性为 `HttpOnly` + `SameSite=Lax`。
服务端通过 `session.get('role')` 判定权限，**不依赖前端隐藏按钮**。

### 2.2 消息反馈（Flash）

所有操作结果通过 `flash(消息, 类别)` 反馈，`base.html` 统一渲染为彩色提示条：

| 类别 | 含义 | 样式 |
|------|------|------|
| `success` | 操作成功 | 绿色 |
| `danger` | 错误 / 被拒绝 | 红色 |
| `warning` | 警告（如需登录、有违约金） | 橙色 |
| `info` | 普通信息 | 蓝色 |

### 2.3 分页参数

四个列表接口（`/books`、`/readers`、`/my`、`/borrows`）共用同一套查询参数：

| 参数 | 类型 | 默认 | 合法范围 | 越界处理 |
|------|------|------|----------|----------|
| `page` | 整数 | 1 | ≥ 1 | 非法值回退为 1 |
| `per_page` | 整数 | 10 | 1–100 | 超出上限截断为 100 |

由 `_page_args()` 统一解析，`_to_int()` 保证非法输入（如 `page=abc`）不会抛异常，而是回退默认值——**任何输入都不应导致 500**。

### 2.4 请求方式说明

- **变更操作**（借书、还书、删除、注销）一律使用 `POST`，避免被 URL 直接触发
- **查询与页面展示**使用 `GET`
- `GET` 型表单页（新增/编辑图书）在**校验失败时直接渲染表单并回显用户输入**，不走重定向，避免已填内容丢失

## 3. 接口详情

### 3.1 `/` — 入口

| 项 | 值 |
|----|----|
| 方法 | GET |
| 权限 | 公开 |

**行为**：根据登录态分流，本身不渲染页面。

| 条件 | 响应 |
|------|------|
| `session` 中有 `user_id` | `302 → /dashboard` |
| 未登录 | `302 → /login` |

### 3.2 `/login` — 登录

| 项 | 值 |
|----|----|
| 方法 | GET（渲染表单）/ POST（提交） |
| 权限 | 公开；**已登录访问时直接跳 `/dashboard`** |

**POST 参数**

| 字段 | 必填 | 说明 |
|------|------|------|
| `username` | 是 | 经 `_clean()` 去空白、截断至 30 字符 |
| `password` | 是 | 不做截断（密码不应被修改） |

**判定逻辑**

```
已登录? ──是──▶ 302 /dashboard
   │否
按 username 查 users
   │
   ├─ 用户不存在 ──────────────┐
   ├─ status != 'active'       ├─▶ flash「用户名或密码错误，或账号已注销」
   ├─ 密码哈希不匹配 ──────────┘    200 渲染 login.html
   │
   └─ 全部通过 ──▶ 写 session ──▶ 302 /dashboard
```

> **安全要点**：三种失败情况返回**完全相同**的提示，不区分"账号不存在"与"密码错误"，
> 避免攻击者通过提示差异枚举有效用户名。

**成功响应**：`302 → /dashboard`，flash 类别 `success`
**失败响应**：`200` 渲染 `login.html`，flash 类别 `danger`

### 3.3 `/register` — 读者注册

| 项 | 值 |
|----|----|
| 方法 | GET / POST |
| 权限 | 公开；**已登录访问时直接跳 `/dashboard`** |

**POST 参数**

| 字段 | 必填 | 校验规则 | 失败提示 |
|------|------|----------|----------|
| `username` | 是 | 3–30 字符，仅字母/数字/下划线 | "用户名只能包含字母、数字、下划线" |
| `password` | 是 | 长度 ≥ 6 | "密码至少 6 位" |
| `name` | 是 | 非空 | "请填写完整的注册信息" |
| `phone` | 否 | 若填则须为 11 位、以 1 开头 | "手机号格式不正确" |

**唯一性**：`username` 重复时捕获 `sqlite3.IntegrityError`，提示"用户名已存在"。

**成功响应**：`302 → /login`，flash「注册成功，请登录」
**行为要点**：新账号固定 `role='reader'`、`status='active'`，**注册接口无法提权**。

### 3.5 `/dashboard` — 控制台

| 项 | 值 |
|----|----|
| 方法 | GET |
| 权限 | 登录 |

**响应**：`200` 渲染 `dashboard.html`

**统计数据**

| 字段 | 读者 | 管理员 |
|------|------|--------|
| `book_kinds` 图书种类 | ✓ | ✓ |
| `book_total` 馆藏总量 | ✓ | ✓ |

> 不在模板里做字符串日期比较。

### 3.6 `/books` — 图书检索

| 项 | 值 |
|----|----|
| 方法 | GET |
| 权限 | 登录 |

**查询参数**

| 参数 | 说明 | 实现 |
|------|------|------|
| `kw` | 关键词，同时匹配书名/作者/ISBN | `LIKE %kw%`，三字段 OR |
| `category` | 分类精确匹配 | `=` |
| `page` / `per_page` | 分页 | 见通用约定 |

**SQL 构造**

```sql
-- 总数查询（与结果查询共用同一 where 片段，保证分页总数一致）
SELECT COUNT(*) FROM books b WHERE 1=1 AND (b.title LIKE ? OR ...) AND b.category=?

-- 结果查询，附带借阅记录数供模板禁用"删除"按钮
SELECT b.*, (SELECT COUNT(*) FROM borrows br WHERE br.book_id = b.id) AS borrow_count
  FROM books b WHERE 1=1 AND ...
 ORDER BY b.id DESC LIMIT ? OFFSET ?
```

**安全**：`kw`、`category` 均经 `_clean()` 清洗并以参数绑定传入，**永不拼接进 SQL 字符串**。

**响应**：`200` 渲染 `books.html`，携带 `pager` 分页信息

---

### 3.7 `/books/new` — 新增图书

| 项 | 值 |
|----|----|
| 方法 | GET / POST |
| 权限 | 管理员 |

**POST 参数与服务端校验**

| 字段 | 类型 | 规则 | 失败提示 |
|------|------|------|----------|
| `title` | 文本 | 必填，≤100 字符 | "请填写书名" |
| `price` | 数值 | 可解析且 ≥ 0 | "价格格式不正确或不能为负数" |
| `total` | 整数 | 1 ≤ n ≤ 100000 | "馆藏总数必须为不小于 1 的整数" / "超出合理范围" |
| `isbn`/`author`/`publisher`/`category` | 文本 | ≤ 100 / 20 字符，可空 | — |

> **校验顺序**：书名 → 价格 → 总数，命中第一个错误即返回，一次只提示一个问题。
> 前端 HTML 的 `required`、`min` 仅用于提升体验，**服务端校验才是唯一防线**。

**成功**：`302 → /books`，flash「图书添加成功」
**失败**：`200` 渲染 `book_form.html`，flash 类别 `danger`，**`form=request.form` 回显用户已填内容**

**库存初始化**：`available = total`（新增时全部可借）。

### 3.8 `/books/<book_id>/edit` — 编辑图书

| 项 | 值 |
|----|----|
| 方法 | GET / POST |
| 权限 | 管理员 |
| 路径参数 | `book_id`（整数） |

**流程**

```
图书不存在? ──是──▶ flash「图书不存在」 302 /books
   │否
POST: 解析表单 → 查未归还数量 borrowed
   │
   ├─ 表单校验失败 ──────────────▶ 400? 否，渲染表单 + 错误提示
   ├─ total < borrowed ──────────▶ flash「该书尚有 N 册未归还, 馆藏总数不能小于 N」
   │
   ▼ 通过
available = max(total - borrowed, 0)   ← 系统反推，不接受手工填写
UPDATE books SET ... available = ? WHERE id = ?
   │
   └─▶ 302 /books，flash「图书信息已更新」
```

**关键点**：可借数由**系统反推**，而非读取表单值——若允许手工填写，管理员可把 `available`
改成与实际借阅不符的数值，破坏库存一致性。

---

### 3.9 `/books/<book_id>/delete` — 删除图书

| 项 | 值 |
|----|----|
| 方法 | POST |
| 权限 | 管理员 |

**校验规则**

```sql
SELECT COUNT(*) FROM borrows WHERE book_id = ?      -- 注意：不带 return_date 条件
```

| 情况 | 结果 |
|------|------|
| `count > 0`（**含已归还记录**） | 拒绝：`flash「该图书已有 N 条借阅记录，为保证凭证完整无法删除」` |
| `count = 0` | 执行 `DELETE FROM books WHERE id=?` |

> **为什么连"已归还"的记录都阻止删除？**
> 若允许删除，该书的借阅记录会指向一个不存在的图书，形成**孤儿记录**；
> 而这些记录又关联读者的借阅凭证，不能连带删除。
> 两难之下选择"有流通记录即不可删"，前端按钮也同步禁用（`books.html` 按 `borrow_count > 0` 置 `disabled`）。

**前端**：`borrow_count > 0` 时删除按钮直接 `disabled` 并带 `title` 说明原因，避免提交后才被拒绝。

### 3.10 `/readers` — 读者列表

| 项 | 值 |
|----|----|
| 方法 | GET |
| 权限 | 管理员 |

```sql
SELECT u.*,
       (SELECT COUNT(*) FROM borrows b
         WHERE b.user_id = u.id AND b.return_date IS NULL) AS borrowing
  FROM users u
 WHERE u.role = 'reader' AND u.status = 'active'   -- 只列未注销读者
 ORDER BY u.id DESC LIMIT ? OFFSET ?
```

**响应**：`200` 渲染 `readers.html`，每位读者带 `borrowing`（在借数量）

### 3.12 `/borrow/<book_id>` — 借书

| 项 | 值 |
|----|----|
| 方法 | POST |
| 权限 | 登录 |
| 路径参数 | `book_id`（整数） |

**前置校验（按顺序）**

| # | 检查 | 失败提示 |
|---|------|----------|
| 1 | 图书是否存在 | "图书不存在" |
| 2 | 是否已借该书且未归还 | "你已借阅该书且尚未归还" |
| 3 | 库存是否充足（在事务内由条件更新判定） | "该图书库存不足，暂无法借阅" |

**核心逻辑**

```python
with db:                                          # 事务：扣库存与写记录要么都成功
    cur = db.execute(
        "UPDATE books SET available = available - 1 WHERE id=? AND available > 0"
    )
    if cur.rowcount == 0:                         # 未更新到任何行 = 已被他人借空
        raise ValueError("该图书库存不足，暂无法借阅")
    db.execute(
        "INSERT INTO borrows(user_id,book_id,borrow_date,due_date) VALUES(?,?,?,?)", ...
    )
```

**成功**：`302 → /my`，flash「借阅成功！请于 YYYY-MM-DD 前归还」
**业务参数**：应还日期 = 借阅日 + `DATABASE_DAYS`（60 天）

### 3.13 `/return/<borrow_id>` — 还书

| 项 | 值 |
|----|----|
| 方法 | POST |
| 权限 | 登录 |
| 路径参数 | `borrow_id`（整数） |

**权限判定**

```python
if br["user_id"] != session["user_id"] and session["role"] != ROLE_ADMIN:
    flash("无权操作他人的借阅记录")
```

即：**本人可还自己的书，管理员可代还任何人的书**，其他读者一律拒绝。

**违约金计算**

```python
overdue_days = (今天 - 应还日).days           # 负数表示未逾期
fine = round(overdue_days * FINE_PER_DAY, 2) if overdue_days > 0 else 0.0
```

| 场景 | `fine` |
|------|--------|
| 按时或提前归还 | `0.0` |
| 逾期 10 天 | `1.0` 元 |

**库存回补**

```sql
UPDATE books SET available = MIN(available + 1, total) WHERE id = ?
```

`MIN()` 是上限保护——即使历史数据异常导致 `available` 偏低，回补后也不会超过 `total`。

**成功**：`302 → /my`
- 有逾期：`flash「已归还，逾期 N 天，违约金 X 元（每天 0.1 元）」`（类别 `warning`）
- 无逾期：`flash「归还成功」`（类别 `success`）

### 3.14 `/my` — 我的借阅

| 项 | 值 |
|----|----|
| 方法 | GET |
| 权限 | 登录 |
| 查询参数 | `page`、`per_page` |

**SQL（含逾期与应计违约金）**

```sql
SELECT br.*, b.title, b.author,
       CASE WHEN br.return_date IS NULL AND br.due_date < ? THEN 1 ELSE 0 END AS overdue,
       CASE WHEN br.return_date IS NULL AND br.due_date < ?
            THEN ROUND((CAST(julianday(?) - julianday(br.due_date) AS INTEGER)) * ?, 2)
            ELSE 0 END AS accrued
  FROM borrows br JOIN books b ON b.id = br.book_id
 WHERE br.user_id = ?
 ORDER BY br.id DESC LIMIT ? OFFSET ?
```

**展示规则**

| 记录状态 | 状态标签 | 金额列 |
|----------|----------|--------|
| 已归还 | 绿色「已归还」 | 实收 `fine` |
| 未还且逾期 | 红色「已逾期」+ 整行高亮 | **应计**违约金（实时增长，标注"应计"） |
| 未还未逾期 | 蓝色「借阅中」 | — |

> 已归还记录显示**已结算金额**，未还逾期记录显示**实时应计金额**——
> 两者含义不同，故分开展示，避免误解为"已经欠费未交"。

### 3.15 `/borrows` — 全馆借阅记录

| 项 | 值 |
|----|----|
| 方法 | GET |
| 权限 | 管理员 |
| 查询参数 | `status`、`kw`、`page`、`per_page` |

**筛选参数**

| 参数 | 取值 | 对应条件 |
|------|------|----------|
| `status` | `on` | `br.return_date IS NULL`（仅在借） |
| `status` | `overdue` | `br.return_date IS NULL AND br.due_date < 今天` |
| `status` | 空 | 不加状态条件 |
| `kw` | 文本 | `b.title LIKE ? OR u.name LIKE ?`（书名或读者姓名） |

**SQL 构造方式**

```python
joins = "FROM borrows br JOIN books b ON b.id=br.book_id JOIN users u ON u.id=br.user_id"
where = ""          # 条件片段独立拼装
if status == "on":  where += " AND br.return_date IS NULL"
...
# 总数与结果共用同一 where，保证分页总数一致
total = db.execute(f"SELECT COUNT(*) {joins} WHERE 1=1{where}", params)
rows  = db.execute(f"SELECT br.*, b.title, u.name AS reader_name {joins} "
                   f"WHERE 1=1{where} ORDER BY br.id DESC LIMIT ? OFFSET ?", ...)
```

> **注意**：不能用 `sql.index("WHERE")` 截取条件片段——当 SQL 含子查询时会截到子查询的 WHERE。
> 本项目改为**显式分段拼装**（`joins` + `where`），从结构上避免这一隐患。

## 4. 错误响应汇总

| HTTP 状态 | 触发场景 | 用户可见表现 |
|-----------|----------|--------------|
| `200` | 正常渲染 / 校验失败回显 | 页面内容或红色错误提示条 |
| `302` | 操作成功后跳转 / 未登录跳转 / 越权跳转 | 跳转目标页 + 提示条 |
| `404` | 访问不存在的路径 | Flask 默认 404 页 |
| `405` | 方法不匹配（如对 GET 路由发 POST） | Flask 默认 405 页 |

**设计原则**：所有**业务层可预期的失败**（校验不通过、库存不足、越权、重复借阅）
一律返回 `200` 并用 flash 提示，**绝不抛 500**——学生填错信息时看到的应该是提示，不是堆栈。
